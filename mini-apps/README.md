# Mini-apps

Two small products built from RiDE's engine-check technology (audio + IMU).
They live in this repository but are **fully separate from the RiDE app**:

| | 送豆腐 `tofu-run/` | 引擎檢測 LINE Bot `engine-line/` |
|---|---|---|
| What | Android game: calibrate with an 18 s engine recording, then ride without "breaking the tofu" | LINE bot + LIFF page: users record their engine, get a result, report problems, chat with the team |
| Runs as | APK (`com.ride78.tofurun`) | Web (Firebase Hosting site) + Cloud Functions codebase `engineline` |
| Firebase project | `motorcycle-verification` (test) | `motorcycle-verification` (test) |
| Firestore | `tofuProfiles`, `tofuCalibrations`, `tofuRuns` | `engineLineUsers`, `engineLineTickets` (+`messages`), `engineLineChecks`, `engineLineStaff` |
| Storage | `tofu/{uid}/…` | `engineLine/…` |

## Isolation rules

- Each app has its **own `package.json` / `node_modules`**. Never install their
  dependencies at the repository root — RiDE's `npx cap sync` would pick up
  their Capacitor plugins.
- They **never import from RiDE's `src/` or `functions/src/`**. Code they reuse
  is copied:
  - tofu-run: small extracts (voice recorder, motion capture) live in its own `src/`.
  - engine-line: `functions/src/shared/` is generated by
    `node mini-apps/engine-line/scripts/sync-shared.mjs` from RiDE's engine-audio
    / IMU / Gemini modules. Don't edit it — edit RiDE's originals and re-run.
- engine-line has **its own `firebase.json`**; RiDE's root `firebase.json` doesn't
  know about it, so a RiDE deploy never touches the bot and vice versa.
- Security rules are the one shared file: their sections are at the end of the
  root `firestore.rules` / `storage.rules` (tests in `tests/rules/`).

## 送豆腐 (tofu-run)

```bash
cd mini-apps/tofu-run
npm install
npm test                 # core game logic
npm run build            # → dist (Firebase config from ../../.env.staging)
npx cap sync android
cd android && ./gradlew :app:assembleDebug
# APK: mini-apps/tofu-run/android/app/build/outputs/apk/debug/app-debug.apk
```

`android/local.properties` (SDK path) is git-ignored — copy it from the root
`android/` folder on a new machine.

## 引擎檢測 LINE Bot (engine-line)

```
engine-line/
  firebase.json         hosting site motorcycle-verification-engine-line + functions codebase engineline
  functions/            lineWebhook, submitEngineCheck, onStaffMessageCreated, simulateLineEvent (asia-east1)
  web/                  "/" = check page (LIFF), "/console" = staff console
  scripts/sync-shared.mjs
```

```bash
cd mini-apps/engine-line/functions && npm install && npm test
cd ../web && npm install && npm test && npm run build
cd .. && firebase deploy --config firebase.json --project motorcycle-verification \
  --only functions:engineline,hosting:motorcycle-verification-engine-line
```

- Check page: https://motorcycle-verification-engine-line.web.app/
- Staff console: https://motorcycle-verification-engine-line.web.app/console
  (log in with a test-project email account; admins are staff automatically,
  others are added on the console's 「成員」 tab by UID)

### Dev mode (now)

The LINE secrets hold the placeholder `UNSET`, so:
- the webhook answers `200 dev mode` and does nothing;
- the check page signs in anonymously and shows the result on the page only;
- the console's **LINE 模擬器** plays a LINE user (`sim-<your uid>`) through the
  real bot logic — tickets appear in 「對話」 and you can reply from there.

### Connecting the real LINE channel

1. LINE Developers → create a **Messaging API** channel (the bot / official account).
   - Webhook URL: `https://asia-east1-motorcycle-verification.cloudfunctions.net/lineWebhook`, turn on "Use webhook".
   - LINE Official Account Manager → turn **off** auto-reply and greeting messages (the bot sends its own).
2. Store its secrets (never commit them):
   ```bash
   firebase functions:secrets:set ENGINE_LINE_CHANNEL_SECRET --project motorcycle-verification
   firebase functions:secrets:set ENGINE_LINE_ACCESS_TOKEN  --project motorcycle-verification
   ```
3. Create a **LINE Login** channel in the same provider → LIFF tab → add an app:
   size *Full*, endpoint `https://motorcycle-verification-engine-line.web.app/`,
   scopes `openid` + `profile`. Link the login channel to the bot (“Linked
   LINE Official Account”) so users get the friend prompt.
4. Put the ids in:
   - `engine-line/functions/.env` → `ENGINE_LINE_LIFF_ID`, `ENGINE_LINE_LOGIN_CHANNEL_ID`
   - `engine-line/web/src/settings.ts` → `LIFF_ID`
5. Rebuild the web app and redeploy (command above). Optional: a rich menu with
   「開始檢測」(LIFF URL) / 「回報問題」 / 「找真人」 / 「我的紀錄」 — those texts are what the bot understands.
